# ЛР3: домены услуги и пользователя

ЛР3 запускается отдельно от ЛР4: `npm run start:lab3`, адрес `http://localhost:3003`, Swagger `http://localhost:3003/swagger`. Для неё автоматически создаётся отдельная база `asteroids_lab3`. ЛР4 продолжает работать на `http://localhost:3000` со своей базой и Redis-сессиями.

Перед запуском ЛР3: `docker compose up -d postgres minio minio-setup`. Требуется Node.js 24+. Настройки PostgreSQL и MinIO берутся из `.env`, отдельные параметры — `POSTGRES_LAB3_DB` и `LAB3_PORT`.

Текущий пользователь ЛР3 фиксирован singleton-функцией `getCurrentObserver()`, id=1. Вход и выход — заглушки для следующей лабораторной: без проверки пароля, cookie, JWT или Redis. Регистрация сохраняет имя и email, но не переключает текущего пользователя.

**Ровно 10 методов: 3 GET, 5 POST, 1 PUT, 1 DELETE.**

| № | Метод | URL | Назначение |
| --- | --- | --- | --- |
| 1 | GET | `/api/dates?maxMonth=7` | Только опубликованные, фильтрация по месяцу; `isCreator: 0/1` |
| 2 | GET | `/api/dates/feed` | Только опубликованные; `isLiked: 0/1`; необязательные `id`, `next=true` для следующей карточки |
| 3 | GET | `/api/dates/draft` | Собственный черновик без id в запросе, не более одной записи |
| 4 | POST | `/api/dates` | Multipart: `designation`, `image`, `video` как файлы, загрузка в MinIO |
| 5 | PUT | `/api/dates/publish` | Публикация собственного черновика: `status=published`, `formedAt` |
| 6 | DELETE | `/api/dates/:id` | Только soft delete собственной карточки, `status=deleted` |
| 7 | POST | `/api/dates/:id/like` | `like: 1` — поставить, `like: 0` — отменить; от текущего пользователя |
| 8 | POST | `/api/users/register` | Регистрация: `fullName`, `email` |
| 9 | POST | `/api/users/auth` | Заглушка аутентификации для ЛР4, необязательный `email` |
| 10 | POST | `/api/users/logout` | Заглушка деавторизации для ЛР4 |

Изображение и короткое видео передаются байтами. Сгенерированные имена вида `date-image-20261018-<uuid>.png` и `date-video-20261018-<uuid>.mp4` содержат латиницу. Сами файлы находятся в MinIO, имена — в полях `image_url` и `video_url` PostgreSQL (названия колонок сохранены для совместимости). В API поля `imageUrl` и `videoUrl` содержат адреса для просмотра этих объектов. Переданные клиентом URL вместо файлов не принимаются.

Импортируйте `postman/LR3_Asteroid_Dates.postman_collection.json`, не коллекцию ЛР4. Cookie и авторизация не нужны. Для выбора файлов рабочая папка Postman — корень проекта; при необходимости укажите `public/assets/default-date.png` и `public/assets/default-date.mp4` вручную. `dateId` для удаления автоматически сохраняется после добавления; `likeDateId` берётся из ленты, чтобы запрос лайка не обращался к уже удалённой карточке.

Варианты ленты и лайка выполняются тем же запросом: включить/выключить `id` и `next` в Params или сменить `like` между `1` и `0`. Это не добавляет методы в коллекцию.

Проверка: `npm run test:lab3`. Тест использует отдельную временную PostgreSQL-базу и настоящий MinIO, сверяет байты файлов, имена в БД, признаки 0/1, ограничение черновика, soft delete, лайки и заглушки. Основная база ЛР4 не изменяется.
